# M2 饮食记录模式交付批次

日期：2026-10-19（北京时间）。本批为 M2 的可回退增量，不代表 M2 整体验收或 M3–M5 完成。

## 本批行为

- 首次启动直接进入饮食日记，不要求性别、生日、身高、体重、活动水平或体重目标；未往 UserDBO 填写任何占位身体数据。
- 主界面只汇总摄入热量、蛋白质、脂肪、碳水；四餐默认收起，显示餐次名、总热量和直接添加按钮，展开才显示食品记录。
- 原身体资料、运动、饮水目标、禁食及身体目标入口退出主导航。设置仅保留热量单位、外观、原数据备份/恢复及食品数据源入口。
- 原身体/运动数据库仍兼容保留；新日记不查询运动记录，创建新的记录日不依赖身体档案、不计算运动补偿。旧记录日的目标字段不被重写，新记录日以 0 表示无目标。
- 移除首页自动免责声明调用，不把用户的免责声明/隐私同意字段伪造为已同意；本 Fork 启动时不再初始化 Sentry。
- 摄入记录编辑支持自由输入 g/mL 或份数；沿用原份量换算和按每100计的存储。更改实际份量后实时显示本次热量，删除需要明确确认。
- 食品详情取消顶部大幅折叠标题、输入时强制滚动及大块占位图；复用缩略图，支持本地食品照片，保留远程照片查看和既有 Unsplash 署名。
- 详情内容区与底部输入区分配实际空间，底部可滚动；不再用覆盖内容加固定200px留白的布局。
- 接入 M1 青绿配色、系统字体、较小的输入/按钮圆角；状态栏按明暗背景选择图标颜色。新摄入摘要按整数四舍五入，避免浮点数使120显示成119；存储、宏量换算和食品营养值不变。

## 架构与数据兼容

主入口 MainScreen 使用 RecordingPage，保留 flutter_bloc/GetIt。查询、编辑、删除复用 CalendarDayBloc 和既有 Usecase/Repository/DataSource；食品添加仍复用 AddMealScreen / MealDetailBloc。记录模式由依赖注入显式启用，保留上游逻辑的独立测试能力。

本 Fork 根据用户明确的中文要求维护 en/zh 字符串；不假定其余语言已完成翻译。

本批未修改 Hive 类型、字段编号或 JSON/CSV schema。上一批新增的可空 nutritionBasisQuantity 继续有效。无 UserDBO 的真实临时 Hive 测试已验证首次保存及重开读取；不存在伪造身体信息绕过初始化。原 Config / User / Activity 数据没有迁移或清空。手机安装前另存了忽略目录内的私有数据快照，不进入 Git。

已修复添加时未等待本地写入就刷新页面的问题，并防止保存中的重复点击；并未把既有多步数据库写入改成事务，不能据此宣称故障时的原子恢复已解决。
