# 内部名称直接显示的专项排查

2026-10-29。用户在手机配方草稿中看到serving，随后要求排查其他类似隐患。本次不提前发布，先查当前可达界面的单位、来源、状态与枚举显示。

## 确认的问题

1. 配方食材数量下拉框、创建/编辑与详情共用食材行，直接显示内部`serving`。这不是数量或单位切换，源代码原来将`unit`原样显示。已将显示文案映射为当前语言的“份”；选项value、配方快照、convertedAmountG及换算函数保持原值。
2. 食品模型确实可能携带历史/占位单位`gml`（例如MealEntity.empty），而部分当前列表/详情/记录说明直接拼接mealUnit或servingUnit，存在显示`gml`的条件隐患。统一使用纯显示映射为`g/ml`，不把它擅自改成g或ml、不改变密度假设或数量。

共用`foodUnitLabel`仅负责展示：serving、gml/g/ml、g、ml、oz、fl.oz/fl oz使用现有本地化文案；未知或用户自定义单位原样保留。没有改存储格式、迁移、数据模型、换算或配方营养算法。
