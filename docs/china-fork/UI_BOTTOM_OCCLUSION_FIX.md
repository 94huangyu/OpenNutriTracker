# 键盘关闭后首页与餐次详情底部空白

2026-10-28。用户反馈：输入或关闭键盘后，首页与餐次详情偶发出现像整块键盘高的白色遮挡，首页底部四导航仍可见；内容只能在上面较小区域内滑动，随后恢复。

后续状态：含本修复的2.4.2（68）已同签名保留数据安装，搜索/记录弹窗/返回及后台恢复等指定实机状态通过，最终完整数据和图片核对相同。原偶发故障仍需日常观察，见 `UI_DEVICE_ACCEPTANCE_242.md`。下文受控复现与本地检查保留其阶段边界。

## 已确认的App布局问题

旧版本的首页外层导航容器、首页和餐次详情均默认启用Scaffold键盘避让。首页和餐次详情没有内嵌输入框；输入发生在独立页面或模态弹窗。

本地在真实页面中复现：打开输入页面、输入、关闭页面并隐藏测试键盘，但模拟平台仍暂报300逻辑像素的键盘遮挡高度。旧首页列表底缘从820缩到600，底部导航仍在900处；餐次详情列表底缘从900缩到600。高度归零后恢复。由此确认，这类延迟高度会让浏览页面错误预留键盘区域，形成空白和缩小的滚动区域。

上述是受控组件复现和App层布局原因。尚未捕获用户手机故障时的系统指标、窗口大小或输入法日志；不能据此断言特定输入法、手机系统或Flutter引擎存在某个已确证的原生缺陷。

## 最小修复

- 导航容器仅在日记标签关闭键盘缩页，食品库、趋势、我的保持原有设置。
- 首页和餐次详情关闭键盘缩页。修改记录弹窗、添加/创建食品、搜索等输入界面保留原有避让。
- 未改焦点处理、系统栏刷新、全局MediaQuery、原生窗口/输入法配置、数据结构、单位计算或记录操作；滑动换日不在本次范围。

焦点检查显示，受检食品库输入框切回首页后已失焦，故没有追加未经需要的全局强制隐藏键盘逻辑。
