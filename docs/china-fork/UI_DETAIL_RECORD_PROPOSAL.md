## D1 食品详情

核对当前 `meal_detail_screen.dart`、`meal_detail_macro_nutrients.dart`、`meal_detail_nutriments_table.dart`、`meal_detail_bottom_sheet.dart` 与 `personal_food_actions.dart`。

- 现状：顶部栏与正文重复显示名称；88 尺寸缩略图、名称、包装量居中纵向排列，后接所选分量热量、三种宏量营养、收藏和核对操作，再到每 100g/ml 营养表。信息纵向较散。
- 建议：顶部栏使用“食品详情”；缩略图、食品名称及来源/规格组成紧凑头部，名称允许换行。保留图片放大与来源署名。
- 建议：热量和碳水/蛋白质/脂肪合并为一个总览，明确写“本次摄入 · 150 g”；下方成分表单独标明“每 100 g”。不混用所选分量和营养标签基准，不改变换算口径。
- 建议：收藏与个人核对在成分表后以普通行呈现，保留核对依据、备注、撤销核对、失效提示及来源说明；重要的数据状态不能只藏在展开内容中。
- 建议：添加区域注明目标日期/餐次，按钮从“添加”改成“添加到午餐”等当前餐次文案，数量输入获得更多宽度。
- 边界：这组示意为从指定餐次进入的添加路径。食品库只读浏览仍不出现添加控件，概览应显示其营养基准而非“本次摄入”。不得为此恢复已取消的食品库记账入口。
- 边界：未知值、已有单位选项、完整营养字段、异步补全、重复添加确认及保存失败保护全部保留；微量营养展开规则仍按现有偏好/数据处理。本提案不改变添加页切换重量单位时的现有分量语义。

## R1 修改记录弹窗

核对当前 `record_intake_sheet.dart`，这是修改一条摄入快照，不是修改食品模板。

- 现状：食品名后是数量/单位等宽两列，下方只有热量，最后依次为实心“保存修改”、描边“再记一份”、文字“删除记录”。
- 建议：补充“修改记录”标题与日期/餐次，食品名置于其下；数量列比单位列更宽，大字体允许分行。
- 建议：输入下方显示本条分量的热量及碳水/蛋白质/脂肪，复用详情/首页相近的信息结构；明确“仅修改这条记录，不更改食品资料”。
- 建议：“保存修改”作为唯一大主按钮；“再记一份”和“删除记录”放在分隔线下，删除使用危险操作色，保留删除后的撤销。
- 评审时已核实的显示问题：原热量使用 `energyPerUnit ?? 0`，能量缺失时会显示为 0。定稿要求仅在缺失时显示“—”，确实为零继续显示 0；各营养值分别判断未知，不能全量补零或反推。2026-10-27 已落实，见实施 V2。
- 边界：保留已实现的 g/份切换保持实际分量、原精度、无效输入校验、保存防重、失败保留输入和撤销删除。再记一份仍增加独立记录，不将其偷换为指定日期餐次的复制功能。
