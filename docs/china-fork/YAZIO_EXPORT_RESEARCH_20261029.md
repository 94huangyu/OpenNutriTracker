# YAZIO 数据导出调研

日期：2026-10-29。范围为公开文档与开源工具静态审查；未登录用户账号、未申请数据副本、未运行导出或开发导入。

## 结论与边界

- 历史饮食记录：有官方数据副本申请途径；也有非官方工具提供逐项日志导出。尚未以用户账号实测，不能把工具自述当作本次导出成功。
- 自建食品：曾记录到导出日期范围内的日记，工具可沿其食品编号尝试获取食品详情；删除、无权限或接口失败仍可能缺失。
- 从未记录的自建食品：审查的工具并未单独枚举“我创建的食品”清单，不能保证覆盖这一部分。请求官方副本时应明确列出全部自建食品，包括未使用的私有及公开食品。
- 未查到当前官方帮助提供全量日记/全部自建食品一键批量CSV或JSON导出的说明；这不等于证明所有版本都没有该按钮。未以竞品营销文章的PRO/PDF说法作为确认依据。

## 官方途径

[YAZIO隐私政策](https://www.yazio.com/en/privacy)，当前页面声明April 2026版本：第15.1节提供个人资料副本申请，第15.6节描述符合条件的结构化、通用、机器可读数据获取。政策未承诺具体导出文件字段或所有食品资料均在副本中。

可经[官方支持表单](https://help.yazio.com/hc/en-us/requests/new)咨询或提出请求。表单说明User ID可从Profile → Settings → Account → User ID复制；不需要把密码提交给客服。

建议在请求中明确范围：全部日期的逐条饮食记录（日期、餐次、食品标识/名称、食用数量及单位、热量及三大营养素）；所有自建食品（包括从未记录的食品、私有食品及自己创建的公开食品，营养基准、份量、单位、条码）；尽量采用JSON或CSV，并说明缺失字段。

[官方自建食品帮助](https://help.yazio.com/hc/en-us/articles/360000629817-How-can-I-create-and-manage-my-own-foods)确认私有/公开食品的区别，并提供Created by me搜索筛选，但未描述批量导出功能。食品和配方不能混为一个范围。

## 非官方工具审查

项目：[1zun4/yazio-exporter](https://github.com/1zun4/yazio-exporter)，本次固定审查树b6eadc395667e239e07a2194d4ea13809001c2a4。README描述CSV、JSON导出，包含nutrition_log、daily_summary、meal_summary、products、product_servings等表，日志中包含日期、餐次、数量、单位及营养字段。

实际[export.rs第145–159行](https://github.com/1zun4/yazio-exporter/blob/b6eadc395667e239e07a2194d4ea13809001c2a4/src/export.rs#L145)：先从consumed.values().products收集product_id，再逐项读取products；并非遍历账户下所有自建食品。api.rs也只有按ID读取食品，没有在该工具中发现枚举全部自建食品的调用。因此不能只看“whole account”宣传就承诺全量自建食品可导出。

作者明确说明不隶属于YAZIO，接口未公开且可能失效。实际使用前需进一步核对登录方式、网络目标和只读范围，并经用户授权在本机验证少量记录；不要求用户在聊天里发送密码。当前未安装或运行该工具。

## 推荐顺序

先向官方索取明确包含日记和全部自建食品的机器可读副本；以实际文件检查覆盖范围。若覆盖不足，再评估经审查的本地只读提取。导出和导入食迹是两项工作：当前没有据此承诺可直接导入，也未改变食迹现有数据。
