## 已确认方案

| 项目 | 现状 | 提议 |
| --- | --- | --- |
| L1 称呼与入口 | 底栏食品库、页标题食谱；食谱/自定义餐食/收藏；加号菜单 | 页标题食品库；我的食品/配方/收藏；显式“＋新建”，保留创建食品、创建配方、导入配方三条既有路径 |

| L3 管理与删除 | 更多菜单合并，旁边另有直接删除；确认框不显示食品名 | 更多中保留编辑、合并和分隔后的红色删除；确认框显示食品名与品牌、历史记录保留说明，取消与删除明确区分 |

“我的食品”仍指当前自建食品，“配方”仍指当前多原料食谱，不合并分类。收藏能力保留，浏览与记录入口的既定区分保留。配方列表保留已有搜索，热量加“合计”提示；不新增个人食品搜索。

## 实施边界与风险

- 冻结预览中的编辑、导入、配方详情和合并只演示入口，删除仅改变临时示例列表；App中的对应入口已接回既有功能，不用示意交互代替实际功能。
- 复用现有食品ID、编辑/删除/合并路径及历史记录保护；合并仍遵守至少两项食品等既有条件，不引入新合并规则。删除收进更多并保留确认，以降低误触。
- 每100g或100ml及热量展示必须读取当前真实基准与换算规则，未知值不能显示成0；不能假定液体密度。预览数值只为比较排版。
- 不修改存储结构、营养算法、默认分类偏好或此前已定稿页面。大字体增加行高，长名称两行后省略；不得用缩字解决拥挤。
